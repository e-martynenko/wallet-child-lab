## Security findings

1. Any payer may create an ATA, but the resulting token account is controlled by
   the recorded owner; setup does not give the payer token authority.
2. The setup uses regular Create, not an assumed idempotent instruction. It may
   run only after finalized evidence says both accounts are absent.
3. After setup, both ATAs must start empty with no delegate or close authority.
4. The `0.005 SOL` ceiling covers this two-ATA slice only; it is not a total
   Mainnet lifecycle budget.

## Unexpected findings

- installed `mpl-toolbox@0.10.0` emits empty instruction data from both
  `createAssociatedToken` and the separately named
  `createIdempotentAssociatedToken` helper;
- the canonical idempotent Associated Token instruction uses discriminator byte
  `1`, so the installed idempotent-named helper was not trusted or used;
- a regular fixed Create plus explicit finalized preflight is clearer than
  manually patching SDK-generated bytes.

## Remaining uncertainty

3. Partial external account creation intentionally stops the fixed setup path

4. Total identity/delegation/setup/funding cost is not yet enforced as one cap.
5. Dedicated RPC, durable metadata, funding route, final simulations, and exact
